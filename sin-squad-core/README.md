# 七罪暗队 · 规则核心 v0.3

按《七罪暗队 · 规则草案 v0.3》实现的规则核心，纯 TypeScript，不含任何画面。
同一份代码同时用于：游戏本体（画面只负责显示和输入）、电脑对手、平衡模拟。

## 使用

```sh
npm install
npm test                          # 28 个测试
npm run typecheck
npm run sim -- roster 60000       # 人物总胜率与最强 / 最弱情境
npm run sim -- opening 400 120    # 开局胜率分布（验收标准：绝大多数落在 30%–80%）
npm run sim -- tables 100 cautious aggressive   # 整张牌桌对局（random / cautious / aggressive / bluff）
```

## 网页试玩

```sh
npm run build:web                 # 打包到仓库根目录的 sin-squad-v3/
```

`web/` 是网页界面的源码：你和电脑 1 对 1，规则全部由这里的核心驱动，界面只负责显示、点击和战斗回放。
打包结果是纯静态文件，本地用任意静态服务器打开仓库根目录下的 `sin-squad-v3/` 即可，GitHub Pages 也能直接托管。

战斗完全确定：同样的输入永远得到同样的结果。牌桌的随机数可以用种子复现。

## 代码里先做了决定、需要确认的地方

规则草案没写死的地方，代码里按下面的方式处理：

1. **护甲的“最少扣 1”按每次攻击算，不按每段算。** 按段算的话，攻 2 的连击打护甲 1 会扣 2、比重击还多，克制环就反了。现在是每段先减到 0，整次攻击只要有一段打中，至少扣 1。
2. **“保持 N 轮”**：条件成立的那一轮算起再保持 N 轮，即连续 N+1 个轮末都成立。持续优势、人数压制需要 3 个轮末；旗手围困、两线推进需要 2 个。
3. **旗手、核心、弱点按人物卡面的基础数值锁定**，装备和下注成长不改变它们。并列取小编号。
4. **饕餮吞掉队友后，空出来的位置对对手公开**（桌上确实少了一张牌），对手因此能推断出饕餮在场。
5. **静默书库**：开战时的能力全部不发动（包括夺装、缔结、魅惑、下注层能力），第 1 轮的战斗能力也失效；沉眠巨像“前两轮不出手”的限制照旧。
6. **夺装者**同时拿走对位的装备；两个夺装者对位时互换。
7. **同行药袋**守护两侧所有相邻队友；攻击被改到它身上后，不再享受“打对位”的加成。
8. **暗标出价相同时**，公共效果不生效，双方都不付钱。
9. **装备**：12 件，6 件身材牌、6 件改形状或加防御，见 `tables.ts`。
10. **市场第三阶段**（第 11 手起的“罪王”级人物）还没有设计，暂时用第二阶段的人物代替。
11. **全押后**不再进行后面的下注和操作；如果胜利规则还没翻开就翻开，但尚未翻开的公共效果不生效。

## 模拟现状（供调平衡参考）

- **开局胜率**：最差一成约 34%、中位约 50%、最好一成约 66%，约 94% 落在 30%–80%，已达标。
- **人物胜率**：多数在 46%–57%；嚼盾兽、无瑕刺客、蓄痛拳手、沉眠巨像略高（56%–57%），窥视者、炫耀者、饕餮偏低（36%–42%）。后三个的价值依赖情报、亮牌和吞噬的决策，随机模拟里的决策很粗糙，会低估它们。
- **牌桌太短**：电脑对手很快全押，一张牌桌平均只打 3–7 手，远少于设计的十几到二十手。需要调整携入金额、底注或下注上限，也需要更好的电脑对手。
