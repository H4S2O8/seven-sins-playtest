# 自由拼词战斗：词库与首轮压测

> **2026-10 更新**：现在有可以直接玩的 Godot 原型，在 `godot/` 目录（双击 `godot/运行游戏.bat`，说明见 `godot/README.md`）。强组合与反制改用真实引擎审计，见 `强组合攻防演练报告.md`。下面的文档是早期纸面设计，其中若与 `godot/README.md` 冲突（行动点节奏、计分制、起手时间、转移/打断的数值等），以 godot 版为准。


本目录是新游戏的设计实验，和旧的七罪、血火及《麦克斯韦妖》原型无关。当前先验证「自由拼词后仍有可获得的反制」；没有宣称已经实现完整游戏或证明所有组合可解。

## 已确认的目标

- 双方各有五张空白随从卡，构筑时分配总计100点给生命和技能数值。生命不计主动技能发动费。
- 技能由实际拿到的词自由拼出；每袋八词，每次公开两袋，双方各取一袋，轮流先选。基础词占多数。
- 一方公开锁定一个行动，另一方看见完整宣告后选择应对，随后双方的行动沿同一条20秒时间轴执行；下一轮交换先手。
- 行动点第1轮新增10、第2轮新增20，依次递增，未用余额保留。每轮之后允许两次逐次公开的词语调整。
- 死亡者完整修整下一轮，之后复出。此次压测暂按「保留已装词和数字，回到本人生命上限，全队同时倒下则败」计算；这几项复出细节仍可调整。
- 三个已讨论状态为狂振、牵连、升华。八种被动关键词在词库第93至100项。
- 直接分流只分配已经投入的数值；组合触发可以产生超出单个词价值的结果。
- 用户允许极强组合成立后取胜。验收重点是：每种被测强组合，是否存在通过常见或少量特定词在实战中较可能拼出的应对。不会把「理论上存在一张稀有答案」算成功。

## 首轮审计约定（待验证假设，不是最终规则）

1. 一个词卡可装到一张角色卡的一个技能中，不能在两张卡上免费复制；`分流` 可从同一个伤害词建立多个数值分支，总额不变。
2. `全部` 覆盖完整指定集合，把同一数值原样给每个目标：写着每人受20点就是每人受20点。`转为` 可以把本来会发生的伤害替换为治疗；本轮不偷偷给它增加转换额度。持续窗口仍受20秒所限。
3. 直接伤害、治疗、增加、减少、减伤须填所用数字，构筑时从总计100点中分配。动态读取「该次伤害」之类的引用按当时实际数值算。复制、范围和触发可以放大结果，重点审计它们的反制可得性。**试验费率为每次主动宣告统一5点启动费，加本次执行分支所有填入的非生命数字之和**；触发读取到的动态数值不再次收费，已装好的触发器后续响应不逐次收费，`重复`再次执行时按重放节点支付数字，不重新收整张技能启动费。支付不足则该技能不能宣告。启动费5为待压测值，不是最终平衡定稿。
4. 非伤害持续效果填写1至20秒，秒数计入构筑预算和该次行动的发动费。单次即时效果不另收持续时间。
5. 一条由某个直接伤害、治疗或施加动作开始的因果链上，同一个装好的词实例最多执行一次；该动作派生的复制、触发与转换保留同一个因果链编号。另一个独立原始动作开启另一条链，同一词实例可以再次响应。此规则让每次命中分别触发，但不让两个词互相转回来无穷运行；合法结构层数不另设上限。
6. 当前待验证的词袋模型：开局随机发12个基础词，包含一套随机基础攻击句和一套随机应对句（自身治疗、自身减伤或「我即将受伤时转移给来源」），两套各用独立词实例，其余随机。每轮展示两袋、每袋20词，允许重复词实例，基础55%、进阶40%、奇术5%，每袋至少10个基础词；常用语法与基础效果抽取权重较高。选牌方看见两袋完整内容。该模型来自用户对基础出招挫败感、进阶词密度和自由拼装多个技能的调整，概率仍非最终定稿。
7. 状态狂振的暂用倍率为造成和受到伤害各+25%；牵连先平分伤害后分别减伤；升华把原定治疗量变成下一次单次伤害增量。固定减伤投资20点对应每段减10，比例减伤投资20点对应50%，可混合。
8. 中立计算对手只根据可见人物、技能和声明行动做出应对；不读取对方未展示的词袋和未来随机数。

## 首轮漏洞后的统一规则（第1次修订）

- `减少 当前生命` 和 `造成伤害` 使用同一套伤害结算与触发；`增加 当前生命` 和 `恢复生命` 使用同一套治疗结算与触发。写法不同可以服务于别的数值组合，但不能借写法绕过减伤、首挡、不屈或伤害转化。
- 20秒时间轴每秒可有多个时间点。同一时间点先建立本刻宣告的状态与限时监听器，再执行移除，再按对双方一致的规则计算伤害、治疗及有限派生链；既有及刚建立的监听器都能响应本刻直接事件。同刻伤害与治疗按净值结算，过量伤害先抵消同刻治疗，不会因为生命先截到0而让1点治疗挡住任意大的伤害。例如原有10生命、受到30伤害、同时治疗1，结果倒下；同时治疗25则剩5生命。倒下与全灭在本刻最终生命确认后检查。出招者当刻已支付、锁定的效果不会仅因同刻倒下而消失。
- 所有同刻执行的直接伤害先合并对每一目标的数值，再按其当前状态结算。分流导致的不同时间点仍各自结算。决定随机目标的种子在宣告前公开，双方对等可见。
- 效果之间仍可能出现互相改写和条件冲突。凡 README 与词库没有进一步定义的复合情况，压测应判作「未定」，不能悄悄任意选择对某一边有利的顺序。

## 审计门槛

强组合先要求具体写出：消耗了哪些词实例、构筑数字、行动点、触发顺序、对手能看到的信息和获胜路径。反制需给出同样具体的合法序列。只有满足下列条件才算通过：

- 不靠临时更改牌意、任意禁用强组合，或补一张只针对该组合的专属词。
- 反制按词袋模型可在对战中合理获得；目标为常见词路线，或者几张特定词形成的明确路线。实际概率需计算，不用「理论上可能抽到」代替。
- 在「先手锁招、后手应对、共同执行」时序下确实来得及；仅存在于赛前完美构筑的反制另行标记。
- 至少有一种反制给出正面收益或迫使强组合改变打法，不能只把失败拖到下一轮。

每轮压测记为「可用词 / 首选强组合 / 实际反制 / 词袋概率 / 结论 / 修订」。验收前不声称全词库都已平衡。

## 当前量化结果与边界

早期 `双人抢词审计.mjs` 不计算重复词实例，仅作历史对照。新版 `词实例并装审计-改道起手.mjs` 在重复词袋、三种随机应对起手、词不能在两个技能中免费共用的条件下运行20,000个随机样本：进攻方第2轮可装“全部敌方伤害”的样本64.67%；这些样本中防守方还能额外装全队急救、全队减伤或全队伤转疗任一路线的为27.95%，第4轮66.35%，第6轮86.64%。这没有把开局保证的一张单体应对卡、生命布局算入，也不是胜率。`转移链核验.mjs` 检查了伤害改道与反噬的四个边界例子。更多待验项见 `审计进度.md`。

用户确认反制可得率约50%可以接受，但这不豁免技能合法性和实战时机审计；一旦反制来不及生效，仍判失败。当前只系统量化了一条强组合路线，不能推断全部强组合都可反制。正在扩大组合搜索范围。
