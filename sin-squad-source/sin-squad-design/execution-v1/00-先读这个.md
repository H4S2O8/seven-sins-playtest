# 七罪暗队：执行框架 v1

日期：2026-09-24。用途：把设计交给下一位执行模型，按小任务实现、按证据验收。

**本包是制作规范，不是已经做好的游戏。** 先完成文本与检查，再由Luna执行助手实操，Astra负责设计裁决和最终验收。用户已授权最终验收合格后发布到GitHub Pages；不是现在发布。主任务不冒充已经切换了模型。

## 1. 要做的游戏

玩家坐在牌桌前，左手持牌，右手边筹码，对面有真实坐着的对手。两位荷官分别给各自负责的一方服务。桌面中央是三对三的小型战场。

每场战斗前，玩家不知道对方三个人物是谁，但能看见对方安装的装备、槽位效果和主攻箭头。双方争夺公共场地效果，花筹码调整自己的配置，判断要继续投入还是弃牌。准备结束才揭开双方小队，自动战斗，按本场规则分配奖池。多场战斗构成一场牌局，直到一方桌上没钱，或玩家在结算后离桌。

不要接回旧的欲望动作游戏、深潜、双面法术链、五格数字牌或编程机甲。这是另一套项目。

## 2. 决策权限与来源

按以下顺序处理冲突：

1. 用户之后明确的新指令。
2. 本执行包明确写出的覆盖项。
3. 父目录各分册的具体卡文、数值、目标与次数。
4. 本包逐角色演出说明。它只能改变表现，不能改能力。
5. 执行者自己的审美和经验。不允许用这一项推翻前四项。

下面标记必须保留：

- **已定**：用户已确认的方向，如第一视角、双荷官、人物正背面、入场几秒且不跳过。
- **制作定稿**：本次为消除实施空白而给出的坐标、时长、文件结构、素材规格。执行时照做；必须修改时记录理由，不偷偷重设计。
- **试制参数**：初始钱包、房间档位、验收帧率、原型规则的限时后备判定等。先按本包跑通，可日后实测调整，不声称平衡结论。
- **未验证**：画面尚未实际复现、战斗尚未实机验证、性能尚未测量。不得改写成“已验证”。

## 6. 实施纪律

每次只完成一张工单：读依赖 → 实现 → 本地测试 → 截图/录屏 → 对照参考 → 记录结果。工单是内部组织方式，不是分批删减交付；最终一次交齐全部298项。共享技术验收失败时先修共享技术，不把错误复制到98人。不要为赶进度删掉动画、改成信息面板或用通用粒子代替角色动作。

若没有可用的图像生成能力，继续做逻辑和测试，但把美术工单标为阻塞；不能悄悄用色块宣称还原。若数值说明存在真实矛盾，记录精确ID、输入和两种结果；不要自行补一个例外规则。

允许低成本调试图用于内部定位，必须加“调试占位”水印，不能作为正式美术交付。资料齐全也不等于执行结果一定合格：必须检查实际画面。
