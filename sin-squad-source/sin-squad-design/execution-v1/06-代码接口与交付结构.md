# 代码接口与交付结构

## 1. 技术路线与职责

Godot 4稳定版，GDScript，Compatibility渲染，单线程Web导出。先记录实际安装版本并固定；不要拿C#、桌面独占着色器或本机文件路径做网页必需依赖。网页需要WebGL2；不支持时给明确说明，不白屏。

本地程序AI对手，不请求在线大模型。Godot客户端可离线玩；Pages只承担静态托管，不冒充真人对战服务器。未来真人版复用纯逻辑与指令，隐藏信息必须移到权威服务端，不能声称当前本地AI版本防作弊。

建议目录：

```text
sin-squad-godot/
  project.godot
  README.md
  core/          纯状态、指令、账本、战斗、规则判定
  content/       298项结构化定义、逐项能力处理器、来源版本
  ai/            仅接受合法观察与行动列表
  presentation/  场景、动画、摄像机、声音、界面
  assets/        正式素材、字体及许可证、切片说明
  tutorial/      教学步骤、固定测试情境
  tests/         无画面逻辑测试、固定对局与断言
  tools/         内容校验、素材检查、打包检查
  evidence/      测试报告、截图索引、已知问题；不混入正式包
```

不在一个大脚本里同时扣筹码、选牌、判胜和播放动画。不用卡面中文字符串匹配来猜能力。

## 2. 数据类型

`ContentDefinition`：id、name、category、source_text、logic_handler、presentation_id、schema_version。人物再有sin、H/A/T/R、reach、armor_kind；装备/槽效记录合法槽类型；规则记录期限和裁定器。数值与卡面同源，卡面不得手写另一套数值。

`UnitState`：固定side/slot、definition_id、hp、initial_max_hp、shield_pools、barrier、statuses、modifiers、next_attack_tick、target_slot、ability_counters、revive_used、final_departed。死亡和最终退场不是同一个可随意混用的布尔值。

`GameState`：schema_version、seed、rng_counters、room_id、hand_id、phase、acting_side、wallet_ledger、teams、round_paid、target_bid、operation_commits、public_effect_queue、revealed_effects、battle_result。私有字段必须可被观察投影剔除。

`Command`：唯一command_id、expected_revision、actor、type、payload。处理返回accepted/reason、新revision、领域事件。过期、越权、重复提交不能再次扣费、换牌或开奖。

`DomainEvent`：event_id、root_id、tick、phase、source、targets、kind、payload、visibility、cause_id。核心只发事实：扣了多少血、是谁造成、剩余盾多少；表现层不自己重新算结果。

金额整数；时间整数tick，每tick=0.1秒；战斗数值用十分之一为整数最小单位。倍率运算在明确步骤向下取到0.1，比较健康度用整数交叉乘或确定性有理数，不用漂移浮点相等判输赢。

## 3. 必须提供的接口

| 接口 | 输入 | 输出与禁止事项 |
|---|---|---|
| ContentRegistry.load | 已校验数据 | 全298项；缺ID、重复ID、未知处理器立即报错 |
| Session.apply | State, Command | 新状态与事件；没有场景树也能运行 |
| Observation.for_side | State, side | 自己全部+对方公开信息；不能只在UI遮住秘密 |
| LegalActions.list | Observation | 当前合法动作、金额区间和原因 |
| Economy.transfer | transaction_id, from, to, amount | 守恒账本；重复ID幂等 |
| Draft.draw | seed,counter,pool,size | 可重放三选一；提交扣费后锁定，重载不重抽 |
| Battle.simulate | 两队、环境、规则 | 事件序列、快照、胜负理由、内容覆盖记录 |
| Rule.evaluate | 固定时刻完整快照、规则内存 | 双方claim/倒计时/限时比较；不读画面状态 |
| AI.choose | Observation, legal_actions, AI seed | 一条合法Command；不读取真实敌队 |
| Presentation.play | 可见事件 | 动画与音效；不反向修改伤害、钱或抽牌 |
| Replay.seek | 初态与指令日志 | 确定性复现；不是正式游戏可倒带作弊入口 |
| Save.commit | 已提交事务后的状态 | user://版本化存档，写入失败有提示 |

## 4. 能力系统如何真正覆盖298项

共享原语只做明确的基础动作：伤害、治疗、自行失血、给/清/耗/移盾、屏障、状态、属性修饰、计数、定时、选目标、安排额外攻击、最终退场与复起。每个内容ID有自己的触发器、条件、资源交换和目标选择，不能用“所有角色都是普攻+按种族随机一个效果”替代。

每个处理器包含订阅事件、是否被沉默、触发条件、代价、结算动作、取消/到期逻辑。source_key包含角色实例与能力ID，不能让两个同名角色共享次数或冷却。

共同防循环：同一root内同一实例能力最多一次；延后派生保留root与已触发集合；多段命中各自根；额外攻击代际标记在所有派生中保留，不得借另一人洗掉。发现超出安全事件预算时测试失败并输出环路，不悄悄吞掉效果继续判胜。

人物、装备、槽效各自处理器，不把沉默误做“这个人所有效果失效”。未实现的处理器只能明确标未实现并阻止正式池发布，禁止回退为白板。

## 5. 同刻结算

读取父目录战斗约定，以其完整细节为准。每一tick先取此刻已安排的独立事件；同刻伤害基于相同阶段的存活快照形成批次，不能先处理玩家就取消敌方原本同时出手。单笔伤害依次经过屏障、护甲、减伤、一次性转移、盾、生命。自伤走独立通道。

事件派生使用有序队列及明确优先级，但不得把该顺序变成同刻胜负优势。同批伤害后处理其有限派生和死亡/复起，全部稳定后统一判胜。治疗不能把一个已经最终退场者当普通活人奶回来；复起须是明确能力。保留原始伤害、护甲阻挡、转移、盾吸收、实际失血、过量伤害的分项日志，玩家点开即可解释“打9为何只扣3”。

来自不同事件的同刻正数治疗与伤害冲突若原稿未覆盖，须单列裁决测试交Astra确认，不用先后顺序暗自决定。所有待裁决不得被报告成已通过。

## 6. 场景与动画层

AppRoot下分Title、Hub、Table、Overlay、Audio。Table包含CameraRig、TableMesh、OpponentActor、两个DealerActor、HandRig、ChipRegions、BattleDiorama和CardAnchors。BattleDiorama固定6个ActorSlot，每个带人物、装备、槽效、条、目标箭头和效果根。

所有位置从单一table_layout资源读取。所有动画从AC编号调用，结束时对齐明确定格；角色动作、受击和材质效果独立轨道。不要让回血打断普攻导致实际战斗比日志少一次攻击。

素材manifest列：asset_id、文件、来源、正背面、尺寸、脚点、关节、动画列表、关联内容ID、是否占位。正式导出遇到required素材缺失或placeholder=true即失败。共享骨架/动作可以复用，但98人的剪影、武器和天赋反馈按04逐个区分。

## 7. 对手与试打

电脑预算自己的筹码风险，用规则、自己真实队伍、公开装备箭头与环境评估要不要牌/场地。对隐藏敌队只能从公开池采样假设，不直接读取。其决策若调试打印，不得把隐私估值发到玩家界面。

先做可解释的程序AI：候选配置在固定几组合法假想敌队上快速模拟，保留一定可复现的保守/诈唬偏好。不是每次都最高价，也不能无限全下。跟注价值考虑整个奖池与自己的实际投入，不把操作费重复算。

“试打”复制自己的状态与公开环境，对面永远是3个标准稻草人；选是否还手。结束后原筹码、人物状态、抽牌计数完全不变。隐藏敌队更换时，同一个己方试打结果必须不变。

## 8. 存档、网页和未来联机

保存钱包、当前房间/手、已提交候选、指令和随机计数。候选公开前后都不能靠刷新免费换三张。网页存储失效要提示“本次进度可能不能保存”。提供导出/导入离线存档，不含执行代码。损坏存档可回到标题但不能默默清空。

Web导出资源用相对路径，放独立子目录；字体本地授权文件，音频首次操作解锁。常见网页导出卡死、首次加载进度、后台标签页暂停、断网重新载入均检查。Pages发布配置采用单线程兼容导出，不依赖COOP/COEP才能启动。

未来服务器只接Command并下发Observation/events；资产表现不影响裁决。此次不承诺多人联机已实现。
